# genEcoli

Migrates the [vEcoli](https://github.com/CovertLab/vEcoli) whole-cell *E. coli* model from vivarium-core (v1) to [process-bigraph](https://github.com/vivarium-collective/process-bigraph) (v2). The migrated simulation produces **identical results** to the original — all 16,321 bulk molecule counts match exactly after 10 simulated seconds.

## Prerequisites

- Python 3.12.9
- [uv](https://docs.astral.sh/uv/) package manager
- Local editable installs of [vEcoli](https://github.com/CovertLab/vEcoli), [process-bigraph](https://github.com/vivarium-collective/process-bigraph), and [bigraph-schema](https://github.com/vivarium-collective/bigraph-schema) (see `pyproject.toml` for paths)
- vEcoli's simulation data (`simData.cPickle`) at `<vEcoli>/out/kb/simData.cPickle`, generated by running vEcoli's ParCa (parameter calculator)

## Quick Start

```bash
# Run the full migration and simulation test (10 simulated seconds)
uv run python tests.py
```

This will:
1. Build the v1 E. coli composite from vEcoli's default config
2. Migrate all 54 biological steps to v2 format
3. Create a process-bigraph Composite
4. Run the simulation for 10 seconds
5. Assert that bulk molecule counts changed (simulation produced results)

## How It Works

### The Migration Pipeline

The migration happens in four stages:

**1. Scan and patch v1 processes** (`scan_update`)

Scans the `ecoli.processes` module tree to find all vivarium v1 `Process` and `Step` subclasses. Each class gets dynamically patched with an `OmniStep` or `OmniProcess` base class via `update_inheritance`, giving it a v2-compatible interface (`inputs()`, `outputs()`, `update()`, `config_schema`).

**2. Build the v1 composite** (`EcoliSim.build_ecoli()`)

Uses vEcoli's `EcoliSim` to load simulation data, instantiate all processes/steps, and generate the initial cell state (bulk molecules, unique molecules, environment).

**3. Translate to v2 state** (`migrate_composite`)

Converts the v1 composite into a v2 state dictionary:
- Each v1 process/step instance becomes a v2 edge with `_type`, `address`, `config`, `instance`, `_inputs`, `_outputs`, and wire mappings (`inputs`/`outputs`)
- The v1 flow (execution order) is encoded as step priorities and synthetic flow-dependency wires that enforce sequential ordering in v2's data-dependency step system
- Mass listener steps are pre-run to seed initial cell mass/volume data
- Port defaults are populated for steps that need them (allocators, listeners)

**4. Run the simulation** (`run_ecoli_sim`)

A custom execution loop that matches v1's execution model exactly:

```
for each timestep:
    for each step in v1 flow order:
        build state view from input wires
        call step.next_update(timestep, view)
        apply update to state via output wires using v1 updaters
    advance global_time
```

This bypasses v2's `Composite.run()` trigger system (which has path-matching limitations for nested state) and instead executes the v1 flow directly on the Composite's state.

### Key Design Decisions

**In-place state updates via wire paths.** v1 processes return delta updates in process-specific formats (e.g., `[(index_array, count_delta), ...]` for bulk molecules). The `apply_step_update` function follows each port's output wire path to the target location in the cell state, then applies the update using the port's v1 updater (callable, `set`, dict merge, or numeric addition).

**Shared UniqueNumpyUpdater instances.** v1's unique molecule system (ribosomes, RNAPs, chromosomes, etc.) uses `UniqueNumpyUpdater` to accumulate `set`/`add`/`delete` operations across multiple steps, then apply them atomically when a `UniqueUpdate` step signals `{"update": True}`. Since v1 shares one updater per Store, and v2 creates independent port schemas per step, `run_ecoli_sim` creates a shared registry of updaters keyed by wire path so all steps accumulate into the same instance.

**Flow dependency injection.** v1 executes steps in a strict sequential order defined by the `flow` dict. v2's step system uses data dependencies (which paths a step reads/writes). To enforce v1's ordering, `inject_flow_dependencies` adds synthetic `_flow_token_{i}` wires between consecutive steps, creating an explicit dependency chain.

**Array writeability management.** v1 makes numpy arrays read-only between steps as a safety measure. The custom loop calls `_make_arrays_writeable` before each step and patches `bulk_numpy_updater` to not re-lock arrays, preventing `ValueError: cannot set WRITEABLE flag` cascades.

### Type System

Custom type handlers registered with bigraph-schema enable serialization/deserialization of scientific data types used throughout the E. coli model:

| Type | Python Class | Purpose |
|------|-------------|---------|
| `unum` | `Unum` | Unit-aware numbers (e.g., concentrations in umol) |
| `quantity` | `pint.Quantity` | Magnitude + unit pairs |
| `csr_matrix` | `scipy.sparse.csr_matrix` | Sparse matrices (stoichiometry) |
| `units_array` | `UnitStructArray` | Structured arrays with units |
| `method` | callable | Function/method references (dividers, updaters) |
| `step_instance` / `process_instance` | v1 Step/Process | Live process instances with port schemas |

## API

### `run_ecoli_sim(composite, flow, interval, timestep=1.0)`

Run the E. coli simulation using the v1 flow execution model.

- `composite`: A v2 `Composite` holding the migrated state
- `flow`: The v1 flow dict (`sim.ecoli.flow`) defining step execution order
- `interval`: Total simulated time to run (seconds)
- `timestep`: Time per step (default 1.0s)

### `migrate_composite(core, sim)`

Translate a built v1 `EcoliSim` composite into a v2-compatible state dict.

### `scan_update(core, path)`

Scan a module path for v1 Process/Step classes and register them with the bigraph-schema core.

## Example

```python
from contextlib import chdir
from bigraph_schema import allocate_core
from process_bigraph import Composite
from wholecell.utils.filepath import ROOT_PATH
from ecoli.experiments.ecoli_master_sim import EcoliSim, CONFIG_DIR_PATH
from genEcoli import scan_update, migrate_composite, run_ecoli_sim
from genEcoli.types import ECOLI_TYPES

# 1. Initialize the bigraph-schema core with E. coli types
core = allocate_core()
core.register_types(ECOLI_TYPES)
core = scan_update(core, 'ecoli.processes')

# 2. Build the v1 composite
with chdir(ROOT_PATH):
    sim = EcoliSim.from_file(CONFIG_DIR_PATH + "default.json")
    sim.build_ecoli()

# 3. Migrate to v2
migrate = migrate_composite(core, sim)
inferred = core.infer(migrate)

# 4. Create the v2 Composite (skip initial step execution)
original_run_steps = Composite.run_steps
Composite.run_steps = lambda self, x: None
ecoli = Composite({'schema': inferred, 'state': migrate}, core=core)
Composite.run_steps = original_run_steps

# 5. Run the simulation
run_ecoli_sim(ecoli, sim.ecoli.flow, 10.0)

# 6. Access results
bulk = ecoli.state['agents']['0']['bulk']
print(f"Global time: {ecoli.state['global_time']}")
print(f"Bulk molecules: {len(bulk['count'])}")
```
